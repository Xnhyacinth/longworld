# P64 authentic long-context taskbank expansion

The completed primary handoff contains **2,486 canonical task instances** across
**15 source worlds** in Finance and CodeForge: **1,953 train / 533 eval**. Source
verification, deterministic task/SFT replay, complete-chat length checks and the
signed readonly snapshot passed. **Strict long-dependency certification remains
zero**; numerical length and valid source-bound answers do not establish it.

## Actual length inventory

All values below count **source context tokens**, with the same pinned tokenizer
for both domains. Capacity bins are disjoint: (32,768,65,536],
(65,536,131,072], (131,072,262,144]. They do not mean every row reaches the upper
endpoint. The primary contexts range from **33,032 to 261,680 tokens**.

| Capacity bin | Train | Eval | Total | Rows within original narrow token interval |
| --- | ---: | ---: | ---: | ---: |
| 64K | 165 | 28 | 193 | 25 within 64,000–65,536 |

| Total | 1,953 | 533 | 2,486 | 97 numerical interval matches |

The narrow interval matches are distributed train/eval as 25/0 at 64K, 4/5 at
128K and 11/52 at 256K. Thus exact-256K **training** coverage is still limited;
the larger 256K-capacity count must not conceal that distinction.

Complete chat sequences, including questions and assistant targets, total
**330,352,112 token exposures**, with a maximum of **261,954**. These exposures
reuse source material; they are not 330M unique knowledge tokens or measured
training compute. No clipping or padding was used to qualify a row. CodeForge
keeps 13 short diagnostics outside the long handoff and rejects one 263,244-token
full message instead of shortening its source or answer.

## What increased

- Finance: eight issuer worlds, 1,682 tasks (1,296 train / 386 eval), 104 distinct
  contexts. New official-source acquisitions are Intel and SiriusXM, four annual
  filings each. The same generic inline adapter supports both, without dedicated
  issuer query functions. SiriusXM quantities remain explicitly as reported in
  each filing; the reorganization is not treated as economic continuity or cause.
- CodeForge: seven repository worlds, 818 source-bank tasks; 804 primary long
  tasks survive full-message checks (657 train /147 eval), with 194 contexts.
  OpenSearch PHP contributes six newly fetched signed PR episodes. Ruff and Oxc
  become represented relative to the P62 qualified-source inventory, but their
  frozen source material already existed. Scikit-learn acquisition was blocked
  by the existing BSD-license detection boundary; that gate was not weakened.
- Across domains there are 298 distinct contexts. Against P63's canonical IDs,
  1,234 task instances are additional: 430 Finance and 804 CodeForge. All 1,252
  P63 Finance task IDs remain; 744 even retain the same sample identity, while
  508 have a different primary context. Those 508 are new views of existing
  tasks, not new semantic tasks. This comparison is not an exhaustive semantic
  equivalence search against every historical LongWorld product.

New finance programs include conditional period selection followed by a
different-metric lookup and sum, exact margin selection followed by cash-flow
lookup, and margin-extreme selection followed by a cash-flow difference. The
last program family is held out from train. It also introduces unseen primitive
operators in eval, so this is **family/operator holdout**, not a pure
known-primitives composition-generalization experiment. P64 source groups are
disjoint internally; legacy training must not be mixed into these eval groups.

## Dependency audit and real shortcuts

All 1,682 Finance samples and all 804 primary CodeForge samples received bounded
support audits. Complete record unions are conservative support supersets, not
minimal proofs. The Finance 4K/8K/16K bound-support coverage is 455/617/649.
Among unchanged P63 tasks, **276 move into a geometry-only strict-candidate class
because the context became longer**, without acquiring a new task or harder
reasoning problem. No such transition is counted as a new strict task.

A new **gold-blind visible-table reader** takes only the public question and
latest required filing's visible text. It reproduces **518/1,682 complete
answers**, including 242 geometry-based strict candidates, from label-selected
cash-flow table crops of **851–1,125 tokens** (at most 1,485 including the
question). It receives no gold amounts, bound answer offsets or hidden XBRL
attributes. Of the matches, 170 use the same required filing; 348 substitute
latest comparative data for the original-filing basis. The latter demonstrate
an answer-metric shortcut, not a valid proof of the original disclosure scope.
The remaining 1,164 cases are unsupported by this narrow reader, not proven
hard or unanswerable.

The CodeForge audit replays answers from compact visible source records. Fifty
of 116 source-bank approval-filter tasks have the same output as their unfiltered
file union; this is an additional instance-level selection-effect diagnostic,
not proof that their source facts are false. Broader model/RAG baselines,
minimal-proof search and counterfactual difficulty validation remain unmeasured.

An explicit 2,486-row audit overlay keeps all rows ineligible for strict training
while distinguishing local table matches, scope-substituting shortcuts and
unresolved dependency cases. It is a companion audit, not a mutation of the
signed primary data or an automatic promotion receipt:
`reports/p64_curriculum_audit_overlay_20260909.jsonl`.
