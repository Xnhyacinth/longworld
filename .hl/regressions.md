# LongWorld must-not-break gates

- Public GitHub replay must receive the exact signed source-client and policy
  SHA allowlist through the isolated child environment; missing pins fail
  closed and are never repaired by re-signing source artifacts.
- Never count candidate/view/length multiplication as semantic scale.
- Never label synthetic executable workflows as authentic source rows.
- Real-source answers must fail when an essential body span is corrupted or
  removed, and factual/CF strict replay must equal their labels.
- Every manifest, source relation, training export, and release package must be
  hash-bound and fail closed on unknown or incomplete inputs.
- Worker-count or caching changes must preserve the exact sorted row-set SHA.
- Generated JSONL, credentials, rejects, and private trust material stay out of
  Git and public release packages.
- A longer bucket must add proof-relevant relations after intersecting visible
  events with that query's sufficient set; unrelated later events already
  present in the packed context cannot count as semantic growth.
- Chained events must fail remove-one in both semantic replay and strict replay;
  `required_inputs` is not a substitute for an actual state dependency.
- Source-grounded query dossiers must exclude every artifact after `spec.as_of`,
  including SourceWorkflow factual and CF artifacts.
- Authentic source relations and synthetic executable edges are separate fields;
  a P7 row missing that provenance split fails closed.
- P7 length increments must add a material amount of proof-bearing or causal
  supporting content, not one short control memo over unrelated workflow bulk.
- Hybrid edge endpoints identify distinct replay events; shared accession IDs
  belong in `source_record_id` and must not collapse the topology into self-loops.
- `scripts/generate.py` hybrid-child detection must be the union of SEC and
  Wikipedia child event types. Wikipedia `wiki_claim_answer` compute/copy
  rungs must appear in `source_relation_edges` / `hybrid_causal_edges` with
  counts 3/6/8 at 16K/32K/64K (causal closure, not essential-only endpoints).
  Replayed `graph.proof_depth` must be 4/5/6 and must match
  `difficulty.proof_depth`. Re-attaching ancestor sections as parallel
  parents of later computes shortens shortest-path depth and fails
  `real_proof_depth_growth`. Empty hybrid edges still make selection report
  zero real workflows.
- Content license must not be inferred from an API access/User-Agent policy.
- Exact-real-64K domain coverage is counted by distinct world as well as row;
  view/timing expansion of one task cannot satisfy a multi-world release gate.
- SEC financial 16K must keep operations plus compute plus two copy rungs
  (four essentials, proof depth 4). 32K/64K must parent the 16K compute, not
  the copies, and must keep essential counts 5 and 10. 128K is allowed only
  when extra issuer-specific sections enter gold (Apple CF/tax/leases/debt;
  not leftover fill of the same MIX/CAT/GEO/BS/CERT program). Pack target
  must exceed the gold estimate; Apple 128k gold ~116k overflowed a 100k cap.
- Wikipedia claim 16K must keep early_work plus compute plus two copy rungs
  (four essentials, proof depth 4). 32K/64K must parent the prior compute, not
  the copies, with essential counts 5 and 7.
- Wikipedia birth evidence may uniquely wrap a duplicated `{{Birth date}}`
  template; CF still requires that wrapper to contain the year once. Do not
  treat a duplicated bare template as a unique span.
