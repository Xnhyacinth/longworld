# P113 scaling program: source-shape × capability × semantic task

Status: active research plan, not a training release. The current corrected P112 bank is described in `.hl/p112_integrated_status.md`. This plan fixes the unit of scaling: a pinned source world and an independently solved semantic task. Domain/topic names, question paraphrases, renderer profiles, and length views are orthogonal exposure controls, not additional semantic worlds.

P113 follow-up: an adversarial review found at least five wrong golds in the first 43-row catalog-driven book shard despite its producer/auditor agreement. That entire shard is quarantined; see `.hl/p113_integrated_status.md`. Source-capacity scale is useful only after the independent semantic truth gate holds.

## Accepted claim and target

Compile many capability tasks from a shared, source-backed world without hand-writing an issuer, book, paper or topic function. Grow source breadth through catalog intake and source-shape routing; grow capability breadth through reusable native operations. Evaluate yield as **independent semantically correct tasks per source and compute cost**, not downloaded files, planned combinations, full-chat tokens or display labels. No forced cross product: every legal and unsupported cell is counted.

A source record needs an immutable content hash, revision or edition, rights state, source-connected split component, genre, original structure, domain/topic labels and detected shapes. Shape examples are typed table with units/notes, revision pair, chaptered narrative with attributed speech, linked documents, repo event history, official rule plus private simulated state, and explicit action-feedback trace. A recipe declares required shape, native oracle, semantic parameter grid, evidence/reader verifier and feasible renderer/length constraints. The planner expands only `source × supported recipe × semantic parameters`; task ID is assigned before rendering and excludes length, position and domain-surface profile.

The native compiler returns a task, gold, evidence lineage, final reader and rejection reason. Final admission requires independent semantic truth, actual model-visible source evidence, a bounded or explicit unknown dependency status, source split, question shortcut review, final chat-template length/evidence offsets, and exact assistant mask. A legal cell can still be rejected. Rejection ledgers remain part of every campaign.

## Next implementation sequence

1. Finish P113 book independent full-text truth/reader/mask audit and preserve its whole-source rejection ledger; leave old 20 quarantined.
2. Extend report reader-context-minus from numeric-surface detection to equivalent-support grouping and answer-underdetermination tests; do not use formal proof-map deletion as a text proof.
3. Add a legal-cell planner over existing native compilers, starting with at least two different real source shapes plus controlled/grounded worlds. Batch jobs use content-addressed receipts, bounded multiprocessing, verified resume and source-connected splits. Each unsupported cell records its structural reason.
4. Render accepted tasks at each feasible coherent length/position layout from original document boundaries. Count the task once; count views and final chat/loss tokens separately. Do not fill length by copying source material.
5. Report coverage by source component, real/simulated boundary, genre, domain/topic, operation mechanism, L1–L4 capability, final length, necessary evidence-token extent, scan load, dependency status and mask status. Show multi-operation shared-world counts and accepted/rejected yield for each source shape.
6. Only after independent gold-blind reader audits and source-connected split certification, build a training-ready selection with explicit task/input/loss-token budgets and equal-budget ablations. No GPU run follows merely from producer replay.

MRCR illustrates cheap payload variation and a fixed executable binding relation, but LongWorld's answer contracts vary by source shape. WildLong's real-query metadata and cross-document composition support breadth; LongFaith's known-gold, citation-grounded supervision supports answer fidelity; DeepReasonQA's evidence graph and path sampling support multi-hop candidates. None of these replaces LongWorld's final-reader truth, scope and dependency checks.
