# P72 执行章程 — 语义丰富与长度补全(2026-09-19 用户裁定)

Status: active。P71 保留为**机制基线**(p71_pool_v1 冻结不改写);本轮在其旁
建新资产,不覆盖。用户最终指令:长度覆盖丰富、world 丰富、真实训练增强
长文能力、减少捷径与虚拟冗长。

## 用户评审的修正(全部接受)

1. **口径统一**:1,504 = 全池 world;1,164 = train 侧;臂行数 ≠ 池行数
   (main 3,972 + extreme 684 = 4,656 是覆盖式不是相加式);"252/252"是行数
   不是 252 种机制(L4 只有 2 结构族)。训练剂量只认 sample_index + 臂 manifest。
2. **"零捷径"降格为"已通过指定探针"**:补同实体错属性对照、
   question↔gold-span 口径、P(Y|metadata) 预测器(非仅熵)。
3. **格式臂必须物化**:渲染函数存在 ≠ 实验材料完成;导出 prose/table 视图
   + token 重测 + gold 复核才算。
4. **长度双峰纠偏**:88% 长输入 token 在 128K;8K/16K/64K 空缺是设计性
   缺陷(K/干扰地板 + 网格没排),下一波补。
5. **密集整合轴**(Oolong 教训):H1 必读 1% 是稀疏访问型;补"逐片段决策
   →全局聚合"型(K/L 高)——注意密集任务天然偏短(必读本身占满上下文),
   与长度补全(8K/16K)是同一波的两个面。
6. **domain 扩展现在并行做**(不等训练):共享机制库 + 领域语义约束 + 有
   内容工件;换字段名不算新 domain,对象/限定/来源/正文真变才算。

  × jsonl/prose/table,ids 相同/gold 字节一致/上下文各异 230K/189K/140K

- **G72-2 长度补全波(p72_short_dense)**:8K/16K/64K 三档进网格。手段:

  8K-128K 连续(不少于 4 档),每档行数 ≥300,门过。

  (K/L 40-80%),Oolong 式 per-fragment+aggregation。验收:必读占比实测
  ≥40%、干预(改任一片段翻聚合)、求解器复核、进测试。

  干预)。domain 合法性 fail-closed(测量→唯一批次→唯一配置、仪器-单位
