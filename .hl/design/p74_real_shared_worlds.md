## 0. 对 P73 的三个收紧判断(生效)

1. **共享上下文 ≠ 共享语义世界**。capability_shared_world.py 现状:各 family
   子世界 → 合并行 → 复用原 family 问题 → 共享文本中回答。records 三族在全部
   合并行上求解(真跨族干扰);F 族仍用自己子世界的行构造 solve_context;
   records 与 F 族不能在同一共享世界中统一求解。下一版不再做
   W = W_filter ∪ W_alias ∪ …,而是先产生统一世界 W,再由 Q₁(W)…Qₘ(W) 访问。
   F 族求解范围必须能从**最终正文与问题中的显式范围**恢复,不能依赖生成器
   知道"哪些行来自哪个子世界"——这是待补契约,不等于判定现有 F 族答案错误。
2. **Witness 分数 ≠ 依赖质量**。latest_text 实际调用正确求解器(任何世界
   零区分);last_declaration 受 spine 单声明约束恒等;ignore_exclusion 结构性
   不影响;部分 relax_one_condition 只是触发查询合法性错误却计入"已区分"。
   拆为三指标:`mutant_applicable` / `mutant_valid_output` /
   `semantic_distinguished`。**语法报错、类型不支持和语义答错不能合成一个
   分数。** C/D 在若干族大量重叠;先修变异有效性与对照组可分性,再谈加
   world 数。
3. **"64K 单档"按实际长度表述**:围绕 64K 目标生成、实际 67K–92K 的一个
   长度簇(中位 75.9K;36/42 落 65536±25%);8K/32K 为零,128K/256K 不在本波。
   Wiki"八行试点"无任何可核验工件,按 **C1 尚未交付**处理,不得作为进展推导。

## 1. 多样性:五张表与扩展形态

| 多样性轴 | 应扩什么 | 不应拿什么替代 |
|---|---|---|
| 主题与知识 | 学科、技术、历史、艺术、地理等真实内容 | 只改标题/topic 标签 |
| 领域过程 | 科研、软件、设备、项目、物流、规范等 | 同一账本换字段名 |
| 任务操作 | 定位、连接、集合、聚合、追踪、规则、状态 | 多个 PROMPTS 改写 |
| 程序组合 | 数据依赖链、分支汇合、例外、回滚 | 同一过滤器增加常量条件 |
| 表达与来源 | 原始文档、表格、邮件、代码、报告、多语言 | ID 变长、JSON key 顺序变化 |

扩展形态:**数百至数千内容主题 × 若干成熟领域过程 adapter × 十几至几十个
基本操作 × 大量合法操作组合 × 多种来源与表达**,不是手写 1000 个 world 生成
脚本。主题与实例广度来自真实资料;操作与状态真值由程序提供。任务族 × 契约 ×
witness 扩大的是**实验设计空间**,不计为"程序空间变丰富"。

## 2. 三层架构

```
资料层:真实正文、表格、代码、规则说明、模拟工件
        ↓
语义世界层:对象、关系、状态、时间、版本、范围、正文证据
        ↓
任务层:定位 / 聚合 / 多跳 / trace / 状态 / 规则学习
```

统一的是**语义对象**,不是强制统一成一种 JSON。示例"观测项目世界":项目、
设备、仪器、人员、机构、观测记录、处理方法、校准状态、方法定义、配置、
版本、修订与撤销、论文、说明文档、运行记录、评审意见。同一仪器可同时是
定位目标、聚合分组键、多跳桥接实体、状态对象、规则输入。

L1–L5 保留为研发分类;domain、文类、长度、位置、证据数是另外的轴,不混成
一个等级。真实资料自然支持 L1–L3;资料中有新规则或足够示例才生成 L4;L5
需实际行动与反馈,单独建设。

## 3. 共享 world 的两个实质检查

1. **事实复用检查**:不同任务真正访问同一对象或事实,不是各自读取互不相交
   的子区块。相同 `context_sha256` 不构成共享语义证据。
2. **跨关系组合检查**:至少一部分任务跨越不同对象类型、文档类型或状态阶段。

## 4. 真实源三路线

- **A:Wiki 目录与关联条目世界**——主题拓展主力。目录/表格 → 条目 → 实体/
  属性/关系 → 关联资料。适配稳定结构(列表/表格、属性、限定关系、来源 span、
  时间与单位),不逐主题写专用代码。
- **B:真实论文与技术资料世界**——自然语义与密集整合。OpenAlex 做主题分层
  采样与分布控制(标签是路由不是 gold,不赋予全文许可);任务逐步进入方法
  定义/实验设置/适用范围/指标口径/结果与局限/主张对应或冲突。
- **C:真实代码与文档世界**——真正的依赖链。仓库文件、接口文档、配置、版本、
  依赖清单、Issue/patch/测试/release。符号定位、调用追踪、配置分支、直接与
  传递影响、版本迁移、测试与修改范围。

Wikipedia 提供模型真正阅读的正文;Wikidata 提供实体链接、别名、关系候选与
限定。**图谱存在某关系但正文无证据,不得用于 gold。** 不用 truthy dump(不含
qualifier/reference);固定查询范围(在给定目录及所附资料中),不得从"图谱
未记录"推断"现实不存在"。

## 5. H 依赖链:绑定变量替代全常量条件

```
LET v = 查询项目在时点 t 采用的规范版本
LET r = 规范 v 对应的有效性规则
LET s = 按 r 筛选的实验对象
LET m = s 对应的测量与修订记录
RETURN 按适用口径比较 m
```

操作集:`Bind / FollowRelation / ResolveVersion / ApplyRule /
JoinOnBoundResult / Group / Aggregate`。后一步的查询键、规则或候选集合来自
前一步,不写死在问题里。区分四个量:语法程序长度、常量条件数、中间变量
依赖深度、状态转移深度。可严谨声明的是"答案在语义上依赖这些中间关系",
**不是**某种算法运行时间下界。

**干预检查**(依赖证书 v0):修改前驱事实(如上游校准规则、后期选择的实验
系列)→ 正确结果变化;修改无关系列 → 不影响答案。

## 6. 证明与证书(下一版最重要的验证模块)

三个概念分开:最小充分证据集(minimal)/ 最小代价证明(minimum,须分别定义
成本:事实数、文档数或操作数)/ 完整上下文中的必要信息(在 E* 中不可删
≠ 在完整 C 中不可绕过——另一份报告、摘要或表格可能提供替代证明)。

证据绑定正文:每事实保存 subject/relation/value/unit/scope/time/version/
supporting_spans/alternative_supporting_spans/source_hash;求解器 proof 引用
正文 span,不是 reveals_events、图谱边或生成器内部对象。

首版:受限操作库中的有界搜索(执行 lineage 得候选证明 → 事实组删除与简化
→ 检查单文档/摘要/表格/重复披露 → 搜索有限数量替代路径 → 记录搜索范围、
预算与是否完成)。后续:AND–OR proof graph(OR 节点=可替代来源,删除必要
事实须处理其等价支持)。不能把图最短路径当通用最短证明。

删除后证明"无法唯一确定",而非 solver 报错:构造 W₁ ⊨ C⁻, W₂ ⊨ C⁻ 且
Q(W₁) ≠ Q(W₂)。删除记录不得因 header 计数不符报错;缺一项不自动=空集;
聚合中非命中记录需审查;真实资料的反事实限定为模拟副本或逻辑补全。

完整上下文必须重检:先验证任务 → 组合最终上下文 → 再验证最终上下文;小
证据通过不得继承到 +200K 正文。D_min = 已认证证明范围内最紧凑连续证据窗口
(考虑同一事实多处出现);只发现部分证明时标注
`proof_search_complete_within_supported_language /
alternative_proofs_checked / minimum_span_within_checked_proofs`。

四种证书,不是一个含义过大的 True:
```
surface_answer_supported
evidence_sufficiency_checked
alternative_proof_scope_checked
long_span_requirement_verified_within_scope
```
闭卷、多模型、单段、RAG 测试补充经验性捷径诊断。不声称永久排除未来模型
参数知识:相对固定模型集与资料快照验证,或用明确模拟的私有状态。

## 7. 长度控制

两种模式:**上限模式**(常规训练主用;不要求贴边,真实长度如实记录)与
**目标区间模式**(课程与受控实验;[B−δ, B+δ],δ 先 ±5% 工程配置)。达不到
就换 world / 按真实关系扩展 / 转其他桶 / 记不可行;**不悄悄降 K/H,不补
无意义字符串。** 窗口预算 L_sys+ctx+query + 答案预留 + 模板 ≤ L_model;
"256K 输入"≠"256K 模型窗口"。

长度控制器管**语义容量**而非只有 length_records:
source_span_budget / entity_count / workstream_count / artifact_count /
candidate_scan_count / dependency_depth / state_history_length /
distractor_budget。三条合法路径分别标注(距离干扰扩展/密集整合扩展/状态图
扩展);"只增加干扰"是有效检索训练增强,但不冒充新增深推理。

一个任务默认一个主长度,少量配对任务测长度与位置效应;加入 48K/96K/192K
非标档验证代码不只对固定档工作。**现在实现 256K 的预算与验证能力,但不要求
P74 首波所有任务生成 256K**;无容量的 world 停在自然长度。

## 8. Renderer 双路

- **A 真实正文保留**(规模化主力):冻结原文 → 解析保留章节/表格/代码 →
  定证据 span → 生成问答;不逐题重写 64K/128K。
- **B 受约束模拟工件**:合法事件与事实 → ContentPlan → 文类/角色/沟通目的
  → 自然文本 → 正文事实回验。同一事实可出现在实验记录/评审意见/技术说明/
  变更通知/工单/会议结论。

JSON、表格、日志、代码都是好数据;问题是训练分布不能只剩一种形式化解释器
输入。

## 9. 准入分流(不放松质量门,新增产品契约)

| Profile | 必须保证 | 不应强制 |
|---|---|---|
| Real-native QA | 原文支持、范围明确、答案验证、来源与许可 | 修改现实事实生成 CF |
| Grounded simulation | 真实规则+模拟状态,正文一致,执行有效 | 所有文本来自现实事件 |
| Controlled mechanism | 程序正确、干预有效、依赖与长度可控 | 已证明自然领域迁移 |

CF 冲突:原始 QA 若有效按 Real-native 审查,CF 作独立模拟变体,不反向污染
原资料。key-order 错配:集合/映射语义在评分与标签规范化处理;有序事件不
无条件排序。真实结构缺失:修来源抽取/问题范围或拒绝,不靠换 profile 放行。
长度不足:进自然长度,不让 128K 规格阻塞有效 32K 任务。不暗改 strict 标准,
不改 production_eligible 权限。

监督 token 差的准确表述:full-provenance→answer-only 的 85.9% 首先是
**删除输出字段的 token 减少**;字段级分解落地前,不宜把全部差值称作纯 ID
token。

## 10. 批处理链与复用粒度

```
Topic/source sampling → 冻结原文、解析、实体链接与证据索引
→ 构建共享语义 world → TaskSpec 批量展开 → 程序执行与非退化检查
→ 最小证明/替代证明/信息不足检查 → 正文与问题表达
→ 长度和位置组合 → 最终正文验证 → 按能力/主题/来源/长度分层输出
```

复用 MRCR Spark 的部分:主题与语言路由、确定性 seed、来源/payload 缓存、
模型请求队列、分片输出、tokenization、去重/manifest/训练导出。LongWorld
特有:对象与关系类型、作用域/单位/版本/时间、可执行查询、共享事实与跨任务
复用、依赖证书。复用粒度:来源解析与许可检查每 source revision 一次;正文
事实与证据验证每 claim/span 版本一次;世界状态与索引每 world 一次;任务求解
与 proof 每语义任务一次;长度/位置/最终 mask 每 view 一次;自然问题表达=
小 TaskSpec+所需证据(非整篇 128K);强模型审计按 profile 与抽样策略。世界
内部演化顺序执行,世界之间并行;普通关系/表格任务 Spark/SQL 展开;状态任务
partition 内执行;模型 API 走幂等队列。

| 工作包 | 改造内容 | 必须交付的证据 |

的示例;某档无合格样本如实为空,不重复 P0 填长。

里程碑二:数百主题、数百至千 source worlds。用实际漏斗定位瓶颈:来源可用率
→ 关系/事实解析率 → 程序可实例化率 → 语义去重保留率 → 正文可答率 → 依赖
profile 通过率。

## 13. 三条边界与首交付物

主题广度≠认知操作广度;最小标注证明≠完整上下文无捷径;可指定长度≠任意
有限资料无损变任意长度。

首交付物:**一个真实 Wiki 或 repo 资料世界,无专属任务脚本,自动产生多种
能力任务;其中存在正文可认证的多跳依赖,并能依据真实语义容量进入 32K/
64K/128K/256K,而不是靠追加同构记录达标。**

## 14. 来源快照契约(v1,本轮两个 agent 的对齐基线)

```
SourceSnapshot {
  snapshot_id, frozen_at,
  source: { kind, license, revisions: {page -> revid}, fetched_via },
  documents: [ { doc_id, title, text, sections } ],
  entities: [ { entity_id, label, aliases, external_qid,
                doc_id, mentions: [ {start, end} ] } ],
  facts: [ { fact_id, subject, relation, value, value_type, unit,
             time, version, qualifiers,
             supporting_spans: [ {doc_id, start, end} ],
             alternative_spans, source_hash } ],
  relations: [ { relation_id, subject, object, relation_type,
                 qualifiers, supporting_spans } ]
}
```

约束:每个 fact 的 supporting_spans 必须指向 documents 的真实文本区间;
图谱事实无正文 span 不得入 facts(可留 relations 候选区并标注 ungrounded);
快照只增不改(frozen);license 与 revid 钉死。T1/T2 编译器消费该契约,
T4 adapter 产出该契约;漂移由 validator 在接线波次裁决。
