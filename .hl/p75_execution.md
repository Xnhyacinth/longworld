# P75 real-reader slice — 2026-09-24

Status: local research candidates, **not train-ready**. Source snapshots and prior P71–P74 products remain immutable. No GPU training or publication was run.

## Result and scope

The P74 bridge and demo used different typing paths. Before this slice, the observatory snapshot produced 0 tasks in the support matrix but 6 locate and 6 as-of candidates in the demo. Structural typing now lives in `wiki_world_bridge.structurally_typed_world` and both callers use it. This is a role inferred from outgoing/incoming fact shape, not a verified domain class. The seven-source support matrix now reports 49 export-budget bank tasks (42 locate, 7 as-of); the Wiki as-of tasks are diagnostic because the snapshots contain no revisions or revocations. Aggregate and multi-hop remain zero on these real snapshots. The matrix's real-Wiki length column comes from P74's raw-document `text-concat` fallback, while its demo column uses the audit render; neither is a final reader length. One world's 40-entry rejection log may be capped, so the program-instantiability denominator is a lower bound.

The bridge now retains alias-surface mentions using the exact document slice, rather than discarding them for failing to contain the canonical label. The observatory snapshot retains all 4,687 mentions, including 1,003 previously dropped alias surfaces. Mutation re-offsetting preserves a mention only while its exact surface remains in the edited text. This repairs an information-loss seam but does not establish that every link target is semantically correct.

The new P75 exporter produces `train.jsonl`, `eval.jsonl`, `sample_index.jsonl`, `audit.jsonl`, `rejects.jsonl`, `source_manifest.jsonl` and `manifest.json` under `data/p75_real_reader_candidates_v1/`. Source documents and a reviewed natural question are in model messages; program, proof, fact IDs, structural evidence checks and source-to-reader offsets are in the audit sidecar. All rows are `research_candidate`; the manifest has `train_ready=false`.

For the frozen seven-source run, 24 candidates passed the current structural row/sentence and question filters: 22 locate plus two source-scoped comparison tasks, with 21 train and 3 eval rows from five eligible source worlds. Two source worlds yielded no candidates. Split is source-world atomic and exact source-title overlap across train/eval is rejected. The three eval questions all concern `easiest_route` in one volcano source world, so this is an export smoke split, not a broad transfer evaluation. Final Qwen chat lengths are 27,617–249,977 tokens; the median is 249,970 because one observatory world contributes 17 rows. Each locate row consumes one fact. The comparison rows each consume two facts from different documents: the two observatory lists report different establishment years (1984/1985) and different location wording for Apache Point Observatory. Both questions ask what the **same named table column** in each source reports; they do not decide which report is correct. Their final inputs are 27,617/27,620 tokens, with fact-value spans about 3,200 tokens apart. This proves a two-source oracle lineage, not that the full visible text lacks an alternate answer path. Physical length and widely spaced entity/proof mentions do **not** establish long-distance necessity for the locate rows. The observed fact-value positions across rows range from 7.8% to 82.3% of the prompt. Actual assistant-only mask verification counted 234 supervised tokens across 24 rows and mapped 48 proof spans to exact prompt-token offsets. `verification.json` records checks and totals.

The validator checks a table row's subject, matching column header and value-cell position, or an infobox key / same-sentence subject–predicate–value expression. It rejects observed malformed markup and a false prose subject. This is stronger than value substring presence, but remains a conservative structural check. Independent gold-blind reading, equivalent-support search, text deletion and license-ready attribution in distributed training rows are still pending. The current candidate set is too narrow for training: it is dominated by locate tasks, its only multi-source pair comes from one object, and its eval contains one relation in one source world.

Independent review caught a four-token difference between the generation prompt and the loader's masked prefix (Qwen thinking markers). Review also caught a negated prose sentence that the first row/sentence checker would accept; the checker now rejects it, with a behavioral regression test. In the two-source pilot, one row has both `Observatory Site` and `Location` columns; its question now explicitly names the `Location` column to keep the gold unambiguous. These fixes changed metadata and admission logic, not historical P74 products.

## Next execution order

1. **Native source evidence.** Preserve table row identity, column label, units, notes, subject link surface and page revision in the source adapter. Keep multi-valued relations separate from state timelines; `fact.time` must mean effect time only when the source supplies that meaning. Run a frozen-source audit on new table-rich Wiki and report sources, counting relation-level supported facts rather than raw spans.
2. **Broaden real multi-evidence recipes.** The first two-source comparison pilot is complete but has only two tasks from one observatory. Expand to more frozen source pairs with clear row units, and test text-level removal including duplicate disclosure. For numeric reports, parse native table schema, execute the same scoped calculation through independent SQL/Python paths, and hide the computed table from the reader. These recipes should yield tasks at 32K/64K when complete documents fit; do not fill a target with repeated text.
3. **Batch production.** Cache parsing and evidence checks per frozen source revision, enumerate supported operation/source cells, run cheap execution and degeneracy filters before long rendering, then generate natural questions from small TaskSpecs and verified evidence units. Keep idempotent teacher requests outside Spark retries. Record candidates, rejects, actual chat tokens, source exposure and per-family support. Use one main length per semantic task, with a small paired-length diagnostic set.
4. **Utility experiment.** After a larger source-diverse set passes an independent reader and source-overlap check, compare fixed-budget old data, real-document compilation and real-document plus state augmentation with identical short replay. Report unseen-source, multi-hop, dense aggregation, MRCR and general-ability readouts separately. No benefit is inferred from the current 24 rows.

## Related-work decisions

[DeepReasonQA/LongPAS](https://aclanthology.org/2026.findings-acl.1306/) supports sampling evidence paths in real Wikipedia and filtering QA, but its path length is not a minimum visible-text proof; its reported SFT run improves some multi-hop tasks while reducing LongBench v2. [LongFaith](https://aclanthology.org/2025.findings-acl.169/) motivates answer-grounded citation supervision once gold/support is known, with a separate gold-blind reader needed for admission. [WildLong](https://arxiv.org/abs/2502.16684) provides a way to sample realistic request forms; its request co-occurrence graph is not a factual dependency graph. [QwenLong-L1.5](https://arxiv.org/abs/2512.12967) supports routing entity-rich, table-rich and open-ended material through different generators. The next LongWorld source adapters should follow that routing while keeping one final reader contract.
