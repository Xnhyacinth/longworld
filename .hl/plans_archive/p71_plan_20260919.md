# P71 — 有限补齐 → 批量合成可比较数据臂 → 训练实验就绪

## Context

P70 审计(2026-09-19,四个 subagent 交叉验证)确认:LongWorld 数据程序按章程在轨、账目诚实、所有抽查数字可复现(v2 银行 3,476 行,869 shard 求解器复核通过,塌缩门 exit 0,560 定向测试全绿)。但完整规模波还有 5 个有限 blocker,其中 2 个是"文档说完成但工件未达标"的真矛盾(L4 split 按 seed 而非规则结构;manifest 缺 budget_recommendation 块)。

用户战略裁定(本轮的最高指令):**保留现有执行核 → 补齐五个有限 blocker → 批量生成可比较的数据臂 → 尽早检验训练收益**。不做宏大重构;不把当前 JSONL 银行盲目扩大十倍后重复 P64;MRCR 式批量合成可以开始(机制并行、成本摊销),但必须走"受约束组合"而非任意笛卡尔积;减少捷径靠"让捷径不再有稳定收益"(错题上下文基线、答案翻转对、插入命中干预、元特征不可预测性),不是把门禁越做越苛。

本轮唯一验收里程碑(用户定义):**同一个版本化银行,能够稳定导出语义可比的主臂、格式臂和机制臂;它们经过一致的正文/依赖验证,并能在相同训练设置下直接比较。** GPU 训练本身保持用户门控(章程红线不动),本轮交付的是解锁条件。

## 执行计划(三条并行工作流,文件作用域互斥)

### Track A — 实验完整性(五个 blocker,按用户依赖顺序)

**A1. L4 规则结构 split 接线 + v2 诚实修正**
- 实测确认(2026-09-19):v2 train 侧 256 parity_vote + 128 threshold_class、eval 侧 64 + 32——两族双侧混杂。`world.json` 各自带**世界局部** `rule.holdout` 声明(自相对、`validate_bundle` 钉定不可改写),缺的是银行级唯一决定。
- 改法(纯 plan 期,生成侧零改动——`rule_family = RULE_FAMILIES[seed % 2]` 是种子纯函数):`make_plan`(`run_capability_records.py:113-115`)对 rule_holdout 族改用 `split_for_rule_family(RULE_FAMILIES[job_seed % 2], trained_rule_family)`;config 新增 `trained_rule_family` 键(进 state);`_rows` fallback(:260)同步;`completion_manifest` 增 `split_basis` + rule_family×split 计数 + **注记:局部 holdout 块是自相对的,导出 split 由银行级决定**;receipt 增 rule_family(增量)。
- **调度混淆必须先解耦**(评审发现 3):v2 的 (rule_family, token_target) 与 seed 奇偶完全混淆——depth-2 threshold 的 32768 槽全 infeasible、parity 独占 131072;结构切分后 held-out 侧可能只剩 depth-1(调度意外,不是设计)。v3 生成前把 rule_family 从 seed%2 解耦(按 cell_index 分层),两侧都排满 (rule_family × depth × token_target) 格;A1 验收加**两侧 depth/target 覆盖断言**。
- 结构选择如实记录:completed parity:threshold = 80:40;trained 配比影响记录。
- L4 三档含义分清(用户要求):structure split = "未见规则族"档(两族下探索性);**trained 族实例泛化档** ——structure split 下 trained 族无 eval 行,本波用 seed 80/20 切 trained 族世界(held-out 族全 eval),或如实写明本波 L4 eval 仅测结构;已见原子规则的未见组合是后续族扩展项。
- v2 银行保持不可变;章程状态行如实修正 G70-4。
- 验收:新波 train/eval rule 结构零交叉 + 两侧 (depth, token_target) 覆盖断言;世界原子性自动保持;manifest 记 holdout_plan dict;新增 runner 级测试(现无)。

**A2. sample_index.jsonl 写入 + config 钉定**
- **先事后路径、后 runner 集成**(评审发现 5 的最优序):同一套索引/预算函数,v2 先回填(验证 schema + 给 v2 一个**非虚真的曝光门**——无索引时门的曝光检查是 vacuous 跳过),runner finalize 调用同一函数。新波 config 先进 configs/ 再生成。
- 索引字段(字面键名,门读 `group_id`+`full_message_tokens`,行字段 `full_chat_tokens` 须映射):example_id(=semantic_task_id)/ world_id / **group_id = world_id** / family / rule_structure_id(**从 shard world.json 的 `rule.rule_family` 读取**——不是重算 seed%2,因 A1 将解耦该耦合) / program_signature / language / renderer(jsonl) / length_records / depth / consumed_records / token_target / input_tokens / supervised_tokens / **full_message_tokens** / output_file / row_index / split / admission_status。索引 sha 绑进 manifest files。
- **A5 后的格式视图行不进本索引**(写一次纪律):视图行进臂 manifest / 独立 view 索引。
- group_id 语义注记:world = 文档类比(世界原子性),不是源广度,如实记录。
- **门的缺字段冒烟测试**:索引缺 `group_id` 时门必须 fail loud,不得静默 doc="None"(当前 v2 无索引时曝光检查 vacuous 通过——这是要修的测量洞,顺带给出 v2 的第一个真实曝光数)。
- 验收:配方 §245 逐字命令(`--index`)在新银行和 v2(事后索引)双口径 exit 0。

**A3. budget_recommendation 进 manifest**
- `recommend_training_budget.py`(:32-81 全在 main)重构出 `derive_budget_report(train_paths, gbs) -> dict`(机械拆分,输出逐字节不变);`run_capability_records.py` 在写 manifest(:504-505)前合入 `budget_recommendation` 块(gbs 一并记录在块旁——它是输入不是推导量;推荐规则版本号写入)。
- v2 走事后路径:独立脚本输出记录进 `.hl/` 注记,不重写 v2 manifest(成本极低,2,784 行)。
- 验收:新 manifest.json 含该块且数值与独立脚本输出一致。

**A4. hash 分层取臂脚本 `scripts/extract_arms.py`(新)**
- 纯 Python 独立脚本(不动 runner)。输入:银行目录 + 臂配额 config(取 A2 索引为成员载体)。
- **hash 作用于 world_id 而非 example_id**(世界原子性);分层维度 = (family, depth, token_target, split, rule_family@rule_holdout——从 A2 索引读)。确定性选择:每 stratum 内按 `sha256(stratum_key|world_id)` 排序取前缀配额(复用 `generate.py:217-225`/`promotion.py:2344` 的 hash 排序惯例,借 idiom 不借代码)。
- **每臂完整导出**(评审发现 11/12):各臂导出自己的 train.jsonl(messages 行)+ 索引切片 + `arms.json` 收据;格式臂的 prose/table 视图**用钉定离线 token 计数器重测 token**(渲染改变上下文长度,jsonl 行的 token 数不可直接拷贝;`_init_worker` 模式)。**eval 保持银行级**,臂是 train 侧导出;"未见 renderer" eval 视图由同一 A4/A5 事后路径渲染(评审发现 12)。
- **臂绑定银行版本**(发现 13):每臂收据记 bank dir + manifest.json sha + config sha——"同一版本化银行"的显式链接。
- 配额诚实纪律:配额从实际池重推导如实记录;极端单元只分层 completed 收据;臂间 overlap 在 arms.json 声明(防拼接双计)。
- 渲染无关性(已核实):`render_world` 是 shard 的**事后确定性视图**(程序+phrasing_index 存于 world.json tasks,无生成期 rng 状态;tamper gate 与 validate_question 交互干净——评审确认)。
- 输出臂:主臂、机制消融臂、格式消融臂(**仅共同支持集**,1,440/3,476=41.4% 当前不可渲染——评审发现 14 修正数字)、L/K/H 极端单元臂。
- 验收:同种子重跑字节一致;配对臂 stratum 行一致;每臂用自己的 train.jsonl+索引过塌缩门;格式臂 token 为实测值。

**A5. renderer 扩展三个 F 族**(`capability_renderers.py`;模块只被测试消费,扩展安全——但评审发现 4:**不是"扩 PROTOCOLS import"级别的小活**,是族分派级重构)
- **核心改法**:五个函数(`_rows_and_family`/`render_world`/`_parse_tagged`/`render_question`/`verify_format_equivalence`)按家族解析**属主模块**(records vs families,runner 的 `FAMILY_MODULES` 惯例);Row 构造、render_context、solve_visible、describe_program、FORMAT_PROMPTS/FORMAT_FIELDS 键、VERSION 全取自属主——renderer 不再硬连 records。
- **prose**:F 族行类型各配模板库+字段模式——alias 行(id/alias/entity/memo)、event 行(id/entity/kind/amount/date/**reveal**,一句两日期)、rule 记录行(x/y 替代 amount/category/date)、demo 行(**points 嵌套列表**新正则 + label);模板选择保持 sha256-over-(VERSION,type,id)(用属主 VERSION)。**asof 折叠顺序承重**(event-date 序):渲染/解析保持文件序,**禁排序**。
- **table**:TABLE_COLUMNS 改 per-family(records 保 7 列;alias 加 alias;asof 加 kind+reveal;rule 用 x,y;demo 需 points,label);空单元格缺席逻辑泛化。
- **契约头**:prose/table 前导增第三行 `# extra: {json}` 携带家族头扩展(rule_holdout 的 rule_family/rule_structure/modulus/labels),`_parse_tagged` 复检。prose 世界必须向读者声明规则结构。
- `lexical_overlap` 证据回退对 asof(event)/rule(demo)误测——一并修。
- **π² 词汇门归类**(发现 15):作为**渲染契约校验**(validate_question 同类),不是难度门——不触碰用户的"不为过门调门"红线。
- 测试:`tests/test_capability_renderers.py` 参数化扩到 families.FAMILIES。
- 验收:六族共同支持集(59.6% 行)100% 三格式渲染且跨格式 gold 字节一致;共同支持集上格式消融臂任务族分布与主臂一致。

```
A1(含调度解耦,唯一生成阻塞) + A2/A3(共享函数,v2 先回填) + A6 + resume 修复
   ├─→ B1 大波(逐族算术, ≥7.8k 候选) ─→ A4 取臂(含 token 重测/银行绑定)─┐
   ├─→ B2 F2 小批实测 ─(达标)→ 并入 B1 增量                               ├─→ C3 冻结 → 训练就绪(用户门控)
   ├─→ A5 renderer F 族(族分派重构,与 B1 并行)───────────────────────────┘
   ├─→ B3 电池(对 B1 产出运行;压缩为错题上下文基线+元特征+词法重叠三项)
   ├─→ B4 unanswerable 适配器(独立新模块)
   ├─→ C1 真实源 adapter(独立文件,里程碑外用户已批准)
   └─→ C2 短锚定夺 + 调研轨(纯读)
Track D(卫生)独立,随时可做
```

**用户红线对照**:solver 过≠模型会学、形状多样≠语义多样、过门≠不塌缩——三条等价替换在 B3 电池与 C3 预注册指标里落实(电池测捷径收益是否归零,实验冻结测训练后行为,门只作风险诊断);0.424 < 60% 目标继续如实标记;L4 不靠两族声称广泛泛化;格式消融只在共同支持集上配对;6K 池≠5K 训练臂的算术按 0.8×0.8 起算;不以行为迁就数字。

## 验证

1. 每项改动:定向 pytest(遵循现有测试布局),比例于 diff;全量套件对照 49F/0E 基线不劣化。
2. 银行 v3:配方逐字验收命令(`--index` 版)双口径 exit 0;求解器复核 100% 进 verification.json;L4 holdout 断言(train 侧 trained 族独占、eval 侧 held-out 族独占);A4 同种子重跑字节一致 + 配对臂 stratum 行一致;A5 共同支持集三格式 gold 字节一致;B3 电池数值进收据(错题上下文 gold 必变、元特征不可预测、词法重叠实测值)。
3. 里程碑验收:同一银行导出主臂/格式臂/机制臂,三臂各自过门、配对 stratum 一致、任务族分布可比——即用户定义的"稳定导出语义可比的数据臂"。
4. 预算纪律:训练步数、行数、文档数、曝光、监督 token 四口径都入 manifest(budget_recommendation 块),实际执行步数训练时回填——预算是上限建议不是许可证明。

## 明确不做

- 不做新一轮平台重构(Spark 推迟到真实源规模波;本地多进程足够 7.8k 候选)。
- 不把 v2 银行重写或覆盖;历史银行不可变,缺陷如实记载。
- 不为过门调门、不放松 fail-closed、不把 padding 计入语义规模(π² 词汇门是渲染契约校验,非难度门)。
- 不启动 GPU 训练(用户门控;本轮交付 C3 冻结文档作为解锁件)。
- 不为凑 30-40% 短锚配比重复采样或虚报。
- 视窗压力下可压缩项(评审):B3 电池三项里只有"错题上下文基线"直接服务捷径削减主张——其余(元特征、词法重叠实测)可顺延;C1/C2/调研轨在里程碑外,随时可让路。
